Gumbel-Softmax: Differentiable Sampling from Discrete Distributions

Some neural networks have to make a choice in the middle of their computation. A discrete VAE picks one entry from a codebook of learned vectors. A reinforcement-learning agent picks one action out of ten. A model that learns to send messages picks one word. The network outputs probabilities, then one option is drawn and used downstream.

Training that network means asking a gradient question: if I nudged these probabilities, how would the final loss change? And the moment you draw a single option, that question has no useful answer. Backpropagation stops at the choice.

In this post, we’ll build up the fix, Gumbel-Softmax, one idea at a time: what sampling is, exactly why it blocks gradients, how a softmax with temperature softens a choice, and how Gumbel noise puts the randomness back. Every figure is a small animation you can pause, restart and play with.

By the end, Gumbel-Max, temperature and the straight-through trick should feel concrete.

Choosing one thing: categorical distributions

A categorical distribution is a list of probabilities over a fixed set of options, one number per option, adding up to 1:

\[ p = [p_1, p_2, \dots, p_n], \qquad \sum_{i=1}^{n} p_i = 1 \]

We’ll use one running example: three categories A, B and C with

\[ p = [0.6,\ 0.3,\ 0.1] \]

A network doesn’t usually output \(p\) directly. It outputs logits \(z\): raw, unbounded scores, one per category. A softmax turns them into probabilities, \(p_i = e^{z_i} / \sum_j e^{z_j}\). Going the other way, \(z_i = \log p_i\) (plus any constant, which softmax ignores). So “logits” and “log-probabilities” are interchangeable for us.

There are two common ways to turn \(p\) into a single choice:

  • argmax: always pick the most likely category. Here that’s A, every time. This is what a classifier does at inference.
  • Sampling: pick category \(i\) with probability \(p_i\). A about 60% of the time, B 30%, C 10%. This is what np.random.choice does, and what an RL agent does when it explores.

A simple way to sample: lay the probabilities end to end along the interval from 0 to 1, draw a uniform random number \(u\), and pick whichever segment it lands in.

TipThink of it as

A playlist where each song has a weight. Shuffle plays songs in proportion to their weights: that’s sampling. “Play my favourite” plays the top-weighted song every time: that’s argmax.

Why a choice blocks backpropagation

Backpropagation needs every step of the computation to answer one question: if my input changes a tiny bit, how much does my output change? That’s the derivative, the slope. Chain enough slopes together and you get the gradient of the loss with respect to every parameter.

So let’s ask that question of argmax. Write its output as a one-hot vector: all zeros, with a single 1 at the chosen category. Now slowly slide the logit \(z_A\) and watch what happens to “is A chosen?”.

The output is piecewise constant: flat, then a jump, then flat. Its slope is 0 almost everywhere, and undefined at the jump. A gradient of 0 tells the optimiser “nothing you change here matters”, which is false, so learning stalls.

Sampling has the same problem in a different form. np.random.choice(3, p=p) returns an integer, and the randomness comes from inside the function. There is no smooth path from \(p\) to the output for a gradient to follow: nudge \(p_A\) from 0.60 to 0.61 and the returned index is either unchanged or jumps to a different category.

The two classic workarounds

REINFORCE (also called the score-function estimator) sidesteps the problem: it never differentiates through the sample, and instead uses \(\nabla_p \log p_i\) of the sampled category, weighted by how good the outcome was. It’s unbiased, but its gradient estimates are noisy (high variance), so training needs many samples or careful tricks.

The reparameterization trick works when the distribution is continuous. To sample from a Gaussian, write \(x = \mu + \sigma \cdot \varepsilon\) with \(\varepsilon \sim \mathcal{N}(0, 1)\). The randomness now lives in \(\varepsilon\), an input that doesn’t depend on the parameters, and \(x\) is a smooth function of \(\mu\) and \(\sigma\). Gradients flow straight through. This is how VAEs train.

Gumbel-Softmax is the reparameterization trick for categorical variables. It needs two ingredients: a smooth stand-in for argmax, and a way to move the randomness into an input.

TipThink of it as

Nudge a song’s weight from 0.60 to 0.61 and “play my favourite” still plays the same song. Turning the knob a little gives you no feedback about which way to turn it.

Ingredient 1: soften the argmax with temperature

The softmax with temperature divides the logits by a number \(\tau > 0\) before the softmax:

\[ \text{softmax}(z / \tau)_i = \frac{e^{z_i/\tau}}{\sum_{j} e^{z_j/\tau}} \]

  • Low temperature (\(\tau \to 0\)): differences between logits get magnified, and the output approaches the one-hot argmax.
  • \(\tau = 1\): the ordinary softmax.
  • High temperature (\(\tau \to \infty\)): differences shrink, and the output approaches uniform, \([\tfrac13, \tfrac13, \tfrac13]\).

Crucially, at every \(\tau\) the output is a smooth function of the logits. Here’s the same experiment as Figure 2, with argmax swapped for softmax.

That fixes the gradient, but it loses something: softmax is deterministic. For the same logits it always returns the same vector. At low temperature it always returns (nearly) the one-hot for A, which is argmax again, not a sample. We need randomness that respects \(p\).

TipThink of it as

Instead of playing one song, a DJ crossfades all of them, each at a volume set by its weight. Temperature is how sharp the crossfade is: at low \(\tau\) you hear almost only the top song, at high \(\tau\) an even mix. Nudge a weight and the mix changes a little: that’s a slope you can learn from.

Ingredient 2: the Gumbel-Max trick

Here’s a remarkable fact. Take the log-probabilities, add a little random noise to each one independently, and take the argmax. If the noise comes from the right distribution, the result is an exact sample from \(p\):

\[ \arg\max_i \big(\log p_i + g_i\big) \;\sim\; \text{Categorical}(p), \qquad g_1, \dots, g_n \overset{\text{iid}}{\sim} \text{Gumbel}(0, 1) \]

The Gumbel distribution describes the maximum of many independent random values (it’s an “extreme value” distribution), which is why it fits so neatly with an argmax. You can draw a standard Gumbel sample from a uniform one:

\[ u \sim \text{Uniform}(0, 1), \qquad g = -\log\big(-\log u\big) \]

Watch it work:

This is the step that moves the randomness into an input. All the randomness is in \(g\), drawn independently of the network’s parameters; the choice itself is a deterministic function, argmax, of \(\log p + g\).

NoteWhy it works (for the curious)

Let \(G_i = \log p_i + g_i\). A standard Gumbel has CDF \(F(x) = e^{-e^{-x}}\), so \(G_i\) has CDF \(F_i(x) = \exp(-p_i e^{-x})\) and density \(f_i(x) = p_i e^{-x} \exp(-p_i e^{-x})\). Category \(k\) wins when \(G_k\) beats every other score:

\[ P(\text{k wins}) = \int f_k(x) \prod_{j \ne k} F_j(x)\, dx = \int p_k e^{-x} \exp\!\Big(-e^{-x} \sum_j p_j\Big) dx = p_k \int e^{-x} e^{-e^{-x}} dx = p_k \]

using \(\sum_j p_j = 1\), and the last integral is 1 because \(e^{-x} e^{-e^{-x}}\) is the Gumbel density itself.

TipThink of it as

Before each song, every track gets a random mood bonus added to its weight (on a log scale), and the player plays whichever ends up on top. With Gumbel-shaped bonuses, each song plays exactly as often as its weight says. Give every track the same bonus and nothing changes: the favourite always wins.

Putting them together: Gumbel-Softmax

Now combine the two ingredients. Gumbel-Max is a perfect sampler with an argmax inside; Ingredient 1 is a smooth stand-in for argmax. Swap one for the other:

\[ y_i = \frac{\exp\big((\log p_i + g_i)/\tau\big)}{\sum_{j} \exp\big((\log p_j + g_j)/\tau\big)}, \qquad g_i \overset{\text{iid}}{\sim} \text{Gumbel}(0, 1) \]

That’s Gumbel-Softmax (also published, at the same time, as the Concrete distribution). The output \(y\) is a soft sample: a probability vector that is random, because of \(g\), and close to one-hot, when \(\tau\) is small. And for a fixed draw of \(g\), \(y\) is a smooth function of \(\log p\), so gradients flow back into whatever produced \(p\).

Choosing the temperature

Temperature trades bias against variance:

Low τ (e.g. 0.1) High τ (e.g. 5)
Samples \(y\) nearly one-hot, close to real samples soft blends, far from real samples
Bias of the gradient small large
Variance of the gradient large: the curve is nearly a step, so slopes are huge near ties and tiny elsewhere small: the curve is gentle everywhere

A common recipe is to anneal: start around \(\tau = 1\), where training is stable, and lower it gradually toward 0.5 or below, so the samples become nearly discrete by the end.

The straight-through trick

Sometimes the downstream computation genuinely needs a discrete choice, for example to look up exactly one codebook vector. The straight-through Gumbel-Softmax uses the hard sample in the forward pass and the soft sample’s gradient in the backward pass:

\[ y_{\text{hard}} = \text{one\_hot}\big(\arg\max_i y_i\big), \qquad y_{\text{st}} = y_{\text{hard}} - \text{stopgrad}(y) + y \]

In the forward pass, \(-\text{stopgrad}(y) + y\) cancels to zero, so the value is exactly \(y_{\text{hard}}\). In the backward pass, \(\text{stopgrad}\) blocks one copy of \(y\) and \(y_{\text{hard}}\) has no gradient, so the gradient is the gradient of \(y\). The gradient is now slightly biased, since it belongs to a different value than the one used, but it works well in practice.

TipThink of it as

Play only the top song after the mood bonus, but learn as if the DJ had played the crossfade.

In code

From scratch, in PyTorch:

import torch
import torch.nn.functional as F

def gumbel_softmax(logits, tau=1.0, hard=False):
    u = torch.rand_like(logits).clamp(1e-10, 1 - 1e-10)
    g = -torch.log(-torch.log(u))             # one Gumbel(0, 1) per category
    y = F.softmax((logits + g) / tau, dim=-1)  # soft sample
    if hard:                                   # straight-through
        y_hard = F.one_hot(y.argmax(dim=-1), y.shape[-1]).to(y.dtype)
        y = y_hard - y.detach() + y
    return y

logits can be unnormalised scores or log-probabilities: softmax ignores a shared constant. PyTorch also ships this as torch.nn.functional.gumbel_softmax(logits, tau, hard).

Cheat sheet

Three ideas that are easy to mix up, and the terms they rely on.

Ideas

Gumbel-Max trick
\(\arg\max_i (\log p_i + g_i)\) with iid Gumbel noise is an exact sample from \(p\). Not differentiable.
Gumbel-Softmax
Replace that argmax with \(\text{softmax}(\cdot/\tau)\). Random, nearly one-hot at low τ, differentiable.
Straight-through
Hard one-hot forward, soft gradient backward.

Terms

Logits
Raw scores a network outputs; softmax turns them into probabilities.
One-hot
All zeros except a single 1 at the chosen category.
Temperature τ
Divides the logits: low τ is sharp, high τ is flat.
Reparameterization
Move the randomness into an input, so the output is a smooth function of the parameters.

The ideas to remember

  1. argmax and sampling output a discrete choice, and a discrete choice has zero or undefined slope, so backpropagation stops there.
  2. Softmax with temperature is a smooth stand-in for argmax: low τ approaches one-hot, high τ approaches uniform.
  3. Gumbel-Max: adding independent Gumbel noise to log-probabilities and taking the argmax gives an exact sample.
  4. Gumbel-Softmax = Gumbel-Max with the argmax replaced by a softmax at temperature τ: random, nearly discrete, and differentiable.
  5. Lower τ means less bias but noisier gradients; anneal it. Use straight-through when the forward pass must be truly discrete.

Back to where we started

The discrete VAE picking a codebook entry, the agent picking an action, the model picking a word: each one used to be a wall that gradients couldn’t cross. Now each choice is \(\text{softmax}\big((\log p + g)/\tau\big)\): the randomness lives in \(g\), the choice is smooth in \(p\), and the network can learn which way to turn every knob. The DALL·E paper used exactly this relaxation, annealing τ toward a small value, to train the discrete VAE that turns images into tokens.
